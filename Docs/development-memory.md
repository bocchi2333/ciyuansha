## 核心架构

- `GameAction`：动作抽象基类，包含 `IsDone` 和逐帧 `Update()`。
- `ActionManager`：继承 Godot `Node`，使用 `LinkedList<GameAction>` 维护动作队列；`AddToBottom` 常规排队，`AddToTop` 用于响应和技能打断。
- `DamageInfo`：记录伤害来源、目标、数值、属性、来源牌及响应/铁索相关状态。
- `DamageAction`：负责指定伤害目标、打开响应窗口、取消或调整伤害、濒死处理、装备修正和属性传导。
- `GameManager`：主规则单例，管理回合、牌堆、弃牌堆、响应、选择窗口、延时锦囊、濒死、胜负和同步快照。
- `LanMultiplayerManager`：局域网连接与主机权威同步。客户端只提交 `NetworkPlayCommand`，主机结算后广播 `MatchStateSnapshot`。
- `StandardDeckDefinition`：固定牌表入口，记录牌型、花色、点数、装备槽和装备效果，不再依赖随机牌堆作为主流程。
- `SkillRegistry`：技能注册唯一入口；`SkillTriggerTiming` 与 `SkillTimingMapper` 统一技能事件时机。
- `GeneralCatalog`：以内置定义兜底，并读取 `Data/general_catalog.json`；还能发现武将图片并生成测试用占位定义。

## 回合与通用结算

- 回合阶段：`TurnStart`、`DrawPhase`、`PlayPhase`、`DiscardPhase`。
- 出牌阶段暂停自动流转，等待本地 UI 输入转换为动作或网络命令。
- 弃牌阶段支持手动弃至手牌上限，然后进入下一名玩家回合。
- 牌堆支持摸牌、弃牌、弃牌堆洗回和测试用牌堆顶部注入。
- 判定牌包含花色与点数，结算后进入弃牌堆。
- 濒死流程按座次打开桃/酒救援，失败后死亡并检查身份胜负。
- 身份基础逻辑包含主公、忠臣、反贼和内奸；2 人烟测使用主公对反贼验证结束条件。
- 通用手牌选择窗口支持选择、公开指定牌、弃牌和主动放弃；窗口打开时动作队列暂停。

- 火攻采用两段交互：目标展示手牌，来源选择弃同花色牌或放弃伤害。
- 借刀杀人支持选择持武器者和被杀目标；拒绝出杀时来源获得武器，成功出杀时继承普通/火/雷属性。

## 武将与技能数据

- `Data/general_catalog.json` 是正式武将数据的主要入口，字段包括 `GeneralId`、`DisplayName`、`Gender`、`MaxHealth`、`CardFileName` 和 `SkillIds`。
- 新技能逻辑注册到 `SkillRegistry`，不得绕过注册表另建分散的技能工厂分支。
- 技能通过 `SkillTriggerTiming` 声明观察时机，例如回合开始、阶段、指定目标、伤害、受伤、牌移动、响应和判定。
- 已有通用技能原型包括主动摸牌、弃牌打击、判定后摸牌、回合外失牌摸牌、首次伤害加成、受伤摸牌和自动闪等。
- 自动发现的武将图片可以进入测试，但正式可玩武将仍需要人工校准技能、体力、性别、阵营和卡图映射。
- 首版内容目标仍建议控制在 8-12 名完成度较高的武将，不一次性为全部图片设计技能。

## 局域网联机

- 支持主机开房、客户端加入、玩家名、端口、选将、准备、开始游戏和返回大厅。
- `NetworkPlayCommandType` 已覆盖选将、准备、重连、出牌、响应和手牌选择等客户端输入。
- `MatchStateSnapshot` 同步阶段、当前玩家、牌堆、角色状态、公开/隐藏手牌、响应与选择窗口、日志和大厅玩家状态。
- 主机是唯一权威结算方；客户端不应直接修改规则状态。
- 对局中断线会保留逻辑座位；同名客户端重连后，主机把新的传输连接映射回原座位并恢复快照。
- 大厅返回时会清理离线的非主机座位，并重置准备状态。
- 默认 UDP 端口为 `24567`，客户端地址支持 `IP:端口`。
- 首轮朋友实测建议继续使用 2 人局，待稳定后再扩大到 3-4 人。
